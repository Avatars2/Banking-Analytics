           EXECUTIVE BANKING ANALYTICS - PROJECT REPORT

1. PROJECT OVERVIEW
--------------------------------------------------------------------
The Banking Customer Analytics System is designed to analyze banking 
customer data to generate strategic business insights. It takes 
static banking records, engineers business-value scores, and feeds 
that enriched data into interactive dashboards so executives can 
immediately see which demographics are churning and which segments 
are the most profitable.

2. HOW THE PROJECT WORKS (THE DATA PIPELINE)
--------------------------------------------------------------------
Like most real-world data analytics projects, this system follows a 
pipeline from raw data to visual insights:

Step 1: Data Ingestion (The Raw Input)
The project starts with raw customer transaction data 
(Churn_Modelling.csv), which acts as a snapshot of the bank's 
customers (containing info like Age, Balance, Tenure, and Geography).

Step 2: Data Transformation & Feature Engineering (The Engine)
The Python script (feature_engineering.py) cleans the data and 
mathematically creates new columns that are vital for business 
decisions. It translates raw numbers into actionable metrics.

Step 3: Data Storage
The newly enriched dataset is saved as 'bank_analytics_ready.csv' 
(and optionally pushed to a MySQL/PostgreSQL database) so it can 
be queried quickly.

Step 4: Data Visualization (The Output)
Instead of spreadsheets, the Streamlit app and Tableau workbooks 
read the processed data and turn it into interactive visual charts 
(KPI metrics, pie charts, and risk matrices).

3. KEY ANALYTICS CONCEPTS APPLIED
--------------------------------------------------------------------
This project is an excellent showcase of four major data analytics 
concepts:

A. Customer Segmentation
   The data is sliced into distinct groups to compare performance:
   - Demographic: Grouping by AgeGroup (e.g., 18-30 vs. 46-60).
   - Behavioral: Grouping by BalanceSegment (Zero, Low, High).

B. Customer Lifetime Value (CLV)
   Instead of just looking at current balances, the system calculates 
   a proxy CLV Score (Balance * Tenure * NumOfProducts / 100). This 
   shifts the focus from "Who has the most money right now?" to 
   "Who is the most profitable long-term?".

C. RFM Analysis (Recency, Frequency, Monetary)
   The code mimics this industry standard by scoring customers 1 to 5:
   - Recency: Tenure (How long they've stayed).
   - Frequency: NumOfProducts (How often they interact/buy).
   - Monetary: Balance + EstimatedSalary (Financial footprint).
   Combining these gives a final 3-15 score that ranks engagement.

D. Churn Risk Modeling
   The project uses rule-based logic to flag "High Risk" customers by 
   isolating people who are older than 40, hold only 1 product, and 
   are currently inactive—providing a targeted list of flight risks.

4. KEY ANALYTICAL INSIGHTS & RECOMMENDATIONS
--------------------------------------------------------------------
- Geographic Vulnerability: Customers in Germany demonstrate a 
  distinctly higher churn rate. Launch focused regional retention 
  marketing campaigns in Germany.
- Age & Risk Dynamics: Customers aged 46-60 exhibit elevated churn 
  behavior despite often maintaining higher average balances. 
  Maintaining loyalty in this bracket is critical.
- Product Engagement Impact: Single-product inactive customers drive 
  the highest churn risk. Develop cross-sell initiatives to convert 
  them into engaged multi-product members.
